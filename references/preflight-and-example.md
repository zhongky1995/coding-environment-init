# 前置问题与一条完整示例

## 按实际场景补漏

先读已有材料与代码，再选出影响本批的类别。下表为候选问题，不是要求用户逐项作答；已有答案直接引用，不涉及的类别跳过。业务选择由用户决定，技术事实与验证安排由 AI 负责。

| 场景 | 本批应查清的业务问题 | 必须接到的方案/验收 |
|---|---|---|
| A 账号与登录 | 怎么登录、注册/恢复由谁处理？停用/注销后已登录设备与数据如何处理？ | 会话有效期与撤销规则；正常、失效、拒绝路径；不凭隐藏入口判定停用 |
| B 租户与隔离 | 一个租户代表什么？人能属于多个租户吗？哪些内容明确共享？退出后数据怎么办？ | 数据归属；适用的列表、详情、搜索、导出、统计、文件、通知的隔离；用不同租户及直接请求验证 |
| C 角色与权限 | 谁能做哪些操作、看谁的数据？谁能分配角色？权限变化何时生效？ | 角色×操作×数据范围矩阵；允许与拒绝都验证；服务端判定和防止自行提权 |
| D 多端 | 哪些端给谁用？是否同步？旧端版本怎样继续工作？ | 各端一致的业务/权限约束、更新后的回读与兼容范围；只测试本批支持的端 |
| E 数据与存储 | 管理哪些对象？刷新/重启后应保留什么？删除能否恢复？旧数据、历史和导入导出怎样处理？ | 数据关系、持久化、迁移与错误样本；适用的数据恢复验证 |
| F 外部服务/AI | 必须接哪些服务、拿到哪些数据？慢/失败怎么办？额度费用和密钥由谁管理？ | 关键真实样本、超时/失败/重复回调、调用上限；mock 与真实集成分开；模型输出另有代表性样本与质量标准 |
| G 支付与金额 | 价格/折扣怎样算？谁可退款、能退多少？回调丢失或重复怎样处理？ | 后台权威计算、金额精度、订单/支付状态、重复扣款与超额退款边界、核对记录；在获准测试环境验证 |
| H 通知与消息 | 哪个事件通知谁、发到哪里？能否关闭？失败重试和频率怎样控制？ | 收件人/租户对应、内容范围、重复/失败处理与发送限额；真实发送遵循授权 |
| I 文件与上传 | 格式/大小/容量？谁能看，能否公开分享、多久过期？删除业务数据后文件怎么办？ | 实际格式校验、访问/分享规则、超限与错误输入、关联清理；拿到链接不自动获得访问权 |
| J 后台/定时任务 | 何时运行、时区是什么？中断或重复执行怎么办？失败谁处理？ | 任务状态、重试与去重、并发/中断恢复、结果/失败可见性；不静默重复产生副作用 |
| K 性能与规模 | 预计数据量和高峰人数？哪些响应时间影响实际工作？ | 带数据量、负载、环境条件的指标与测量方式；不凭空套用秒数/并发目标 |
| L 隐私与适用要求 | 哪些信息必要、谁能看？要不要脱敏、操作记录、删除/保留？有哪些明确适用要求？ | 最小数据范围、关键操作记录、日志/错误展示、数据处理规则；未核实的法规判断不冒充已满足 |
| M 运维与上线 | 部署在哪、开发/测试/正式如何区分？谁负责费用、故障、恢复？ | 发布与恢复路径、日志/告警入口、环境与配额；本批只落必要准备，上线专属验证排到发布前 |

把答案直接写入需求/规则有效位置，给相应验收项标 ID，不另建一份场景答案库。区分「已确认」「实现观察」「待验证假设」；已有实现不自动成为用户已认可规则。

## 示例：第一批报销交付（示例假设，不能复制成真实授权）

用户目标：团队能完成一次报销申请与审批。尚未讨论财务支付。

1. **先查事实**：现有登录、员工归属、申请表结构与测试入口。原本已坏的登录单独记录。
2. **只问本批业务空缺**：经理管哪些员工、是否允许撤回。支付、发票识别和报表留到后续。
3. **形成 current-task**：M1 = 员工提交 → 经理审批 → 员工查看结果；允许改申请页面、对应接口和必要存储；保持现有组织归属和权限规则。记录用户实际授权，不能写「已批准」占位。
4. **先定验收，再拆步骤**：

| ID | 输入/操作 | 预期 |
|---|---|---|
| A1 | 员工甲提交申请，刷新页面 | 申请仍在且金额一致 |
| A2 | 有权限的经理批准，员工甲再次查看 | 状态与审批意见一致 |
| A3 | 员工乙从页面和直接请求读取甲的申请 | 均不能取得申请内容 |
| A4 | 提交按钮重复点击/请求重发 | 按已确认规则只产生一笔有效申请 |

5. **current-todo 消费这些定义**：S1 打通提交、持久化和查看（A1）；S2 审批和结果回读，依赖 S1（A2）；S3 补齐本批越权与重复请求边界（A3、A4），相关防护随实现加入，不把权限整体拖到最后。
6. **实际结果写回**：S1 完成时 A1 通过，A2 未实现；不把 A2 记为测试失败，也不宣称整批完成。每条证据带代码状态、运行条件和定位入口。
7. **换对话**：接手者读 M1、S2、对应权限规则和代码入口；核对 S1 后的变动。现场相符就继续 S2，不重复问谁能审批。
8. **交付**：在整合版本完成 A1–A4 和受影响旧能力检查。给用户两个测试身份的获取方式与试用入口，凭据不写入版本化文档。

这条路径可由一个会话持续执行。只有真实分工收益或独立性要求才引入总控与工作者。
