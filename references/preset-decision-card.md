# 选档决策卡

此卡只在已选择软件开发分支后使用。客户交付工作区按材料和实际工作线裁剪，不因“长期”“多任务”而默认使用guided或expanded开发模板。

档位决定记录详细程度，不决定是否需要业务判断、运行环境或更多工作者。先看已有记录是否足够，再选择本批所需的补充。

| 当前情况 | 默认动作 |
|---|---|
| 已有充分入口，只是修一个小问题 | 复用，不重新初始化 |
| 明确小闭环，需要建立入口 | minimal；计划/证据留在 current-task |
| 多步或跨会话开发 | guided；current-todo 保存唯一进度与交接 |
| 详细需求、架构、QA 已需分别维护 | expanded；引用既有同义文档，避免复制 |
| 新项目只有一条简单流程 | guided 足够；照常完成必要前置确认与可运行仓库准备 |
| 业务关键选择缺失 | 查材料、提出具体选择；只暂停依赖它的实施 |
| 技术条件会推翻方案 | 先做限时/限定调用的小实验，不靠增加文档解决 |
| 已有别的有效任务/进度体系 | 保留其入口和职责，只补缺口，不新建重复状态 |
| 同类错误反复出现 | 针对原因加可重复检查，不加厚入口或重启验收 |

拿不准档位时先 guided。新项目、跨模块或「重要」不单独触发 expanded。只需更新一份现有记录时更轻。

对用户说明本批成果、选档理由、实际准备状态、如何证明和还需什么决定，不让用户在文件档位之间猜。
