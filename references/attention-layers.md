# 注意力与记录职责

让方向依据独立于单个对话保存。下表是维护职责，不是新增文件清单；复用现有命名，小项目可合并，其他入口链接同一来源。凭据不写入版本化文件。

| 内容 | 放置位置 |
|---|---|
| 整体目的、使用者、预期结果及原始依据 | 现有项目说明或产品/合作约定；project-context 指向它 |
| 有效设计、结构关系、关键取舍及变更依据 | 现有设计/业务规则；开发项目可用 architecture-guardrails 链接详细设计 |
| 本轮交付、授权、验收定义及其与整体目标的关系 | current-task 或已有当前任务 |
| 当前成品、实际验证、未解决偏差及内部进度 | 现有成果与执行记录；minimal 放 current-task，guided 放 current-todo |
| 工具/个人的长期行为规则 | 外层指令；不反复抄入项目 |

## AGENTS 与目录入口

AGENTS（或宿主使用的等价入口）保持简短：指向整体目标、有效设计、当前成果和任务的维护位置，说明何时更新哪一处。局部 AGENTS 补充适用目录的职责，不能以局部目标替换整体约定。保留现有人工内容与指令优先级；项目入口不能冒充系统级强制机制。

接手时沿入口核对本轮任务与目标、设计和实际成果的关系；方向变化按 [执行与接续](execution-and-handoff.md) 的依据处理。不要把上一会话的总结或最新日期自动当作有效性证明，也不要求每轮重新确认已明确的目标。

目录调整服务材料查找和责任归属。优先保持现有布局，区分有效成果、候选和历史材料，避免每次会话另建一套目录。移动文件时保护原件并更新受影响引用；入口过期就修入口，不因此全量重整仓库。

维护后实际沿接手入口走读，确认能定位目标及来源、有效设计及理由、当前成果和下一步，且不存在需要接手者自行猜选的冲突基准。局部工作只检查受影响的入口；文件存在或链接可达不能证明方向正确。

不新增独立 Iteration Reminder。旧契约/提醒模板仅为兼容入口，内容归并进现有任务与计划，不维护两套状态。可自动检测且确有重复价值的边界再进入 lint/测试/CI；语义判断仍需结合实际成果。
